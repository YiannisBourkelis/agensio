# Design: per-site users and generated php-fpm pools (C3b)

Status: accepted 2026-09-17 (every question below as proposed) and built the same day
(C3b-1, C3b-2, C3b-3). One change from the proposal: per-site logs are
`agensio:<site group> 0640` rather than `<user>:<agensio group> 0640`, because agensio
must reopen them after a SIGUSR1 once it has dropped privileges, and as owner it can;
the customer still reads through their group.

## Goal

`user = "web1"` on a site makes agensio responsible for the isolation that hosting
panels (ISPConfig, Plesk, the IIS application-pool model) assemble by hand today:

- PHP for that site runs as `web1` only, in its own php-fpm pool, with a private tmp
  and session directory and `open_basedir` at the project root;
- the pool socket is owned by `web1`, group-readable by agensio, and nothing else;
- the site's logs are owned by `web1` so the customer can read them and other customers
  cannot;
- `agensio -t` refuses a configuration in which one site could read another's files,
  socket or logs, naming the file and the mode that is wrong.

Not in scope here: running php-fpm itself, starting as root and dropping privileges
(H2), kernel containment of the web server (H3b), one agensio process per site user
(a later idea in the roadmap), and the control API command `sites/create` (F) which
will call the same code.

## Configuration

```toml
[server]
group = "agensio"                 # the group agensio runs as; pool sockets grant it access
pools = "/etc/php/8.3/fpm/pool.d" # where generated pool files go (`agensio pools`)

[[site]]
server_name = ["shop.example.com"]
listen = ["0.0.0.0:443"]
root = "/var/www/clients/web1/shop"
user = "web1"                     # everything below follows from this
group = "client1"                 # optional, default: web1's primary group
app = "laravel"
php = { children = 8, version = "8.3" }   # no socket: generated, see below
```

Rules:

- A site with `user` and an `app` (or any FastCGI location) without `php.socket` gets a
  generated pool. Its socket is `<pools_run>/agensio-<user>.sock` where `pools_run` is
  `/run/php` on Debian and `/run/php-fpm` on RHEL, overridable with
  `[server] pools_run`.
- Two sites with the same `user` share one pool (one customer, several sites) as long as
  their `php` sizing agrees, otherwise `-t` says which key differs. Sites with different
  users never share a socket, even if they say so.
- A site with `user` and an explicit `php.socket` is allowed (an existing pool) but the
  ownership rules below still apply to that socket.
- `php` keys for a generated pool: `children` (pm static count, default 8), `version`
  (default: the newest installed), `max_requests` (500), `memory_limit` ("256M"),
  `max_execution_time` (60 s), `upload_max_filesize` (from `max_body_size`),
  `open_basedir` (default: the site root, its private tmp and session directories;
  Laravel adds the project directory above `public/`), `extra = { key = value }` passed
  through verbatim as `php_admin_value`.
- agensio's own FastCGI options for a generated pool default to `keep_conn = true` with
  `max_connections = children / workers` (rounded down, at least 1), which is the sizing
  C3a required. The user can still override them.

## The generated pool file

```ini
; generated by agensio from /etc/agensio/agensio.toml, site shop.example.com; do not edit
[agensio-web1]
user = web1
group = client1
listen = /run/php/agensio-web1.sock
listen.owner = web1
listen.group = agensio
listen.mode = 0660
pm = static
pm.max_children = 8
pm.max_requests = 500
catch_workers_output = yes
clear_env = yes
env[PATH] = /usr/local/bin:/usr/bin:/bin
php_admin_value[open_basedir] = /var/www/clients/web1/shop:/var/lib/agensio/web1/tmp:/var/lib/agensio/web1/sessions
php_admin_value[upload_tmp_dir] = /var/lib/agensio/web1/tmp
php_admin_value[sys_temp_dir] = /var/lib/agensio/web1/tmp
php_admin_value[session.save_path] = /var/lib/agensio/web1/sessions
php_admin_value[memory_limit] = 256M
php_admin_value[max_execution_time] = 60
php_admin_value[upload_max_filesize] = 64M
php_admin_value[post_max_size] = 64M
php_admin_flag[expose_php] = off
php_admin_value[disable_functions] = 
```

`/var/lib/agensio/<user>/{tmp,sessions}` are created `0700 <user>:<group>`. The
directory root is `[server] state_dir`, default `/var/lib/agensio`.

## Commands

- `agensio pools [-c file] [--out DIR] [--diff] [--dry-run]`: writes one pool file per
  generated pool into `--out` (default `[server] pools`), creates the state
  directories, removes generated files whose site is gone (only files carrying the
  header), and prints what changed. Exit status 0 when nothing changed, 3 when files
  were written so a script knows to reload php-fpm (`systemctl reload php8.3-fpm`).
  agensio never signals php-fpm itself in this phase; the reload is the caller's, and
  later the control API's.
- `agensio -t` also runs every validation rule below and reports each failure with the
  path, the current owner and mode, and the expected one.
- `agensio -t --explain` shows the generated pool for each site, like presets today.

Writing into `/etc/php/.../pool.d` needs root; `agensio pools` is meant to be run by the
administrator or a panel, not by the server process.

## Validation rules (`agensio -t`, refuse on failure)

For every site with `user`:

1. The user and group exist.
2. The site root and everything `open_basedir` names are owned by the site user or
   root, and are not writable by other users (no group or world write bits unless the
   group is the site's own group).
3. No path under the site root that the preset knows to be secret (`.env`, `config/`,
   `storage/` for Laravel; `wp-config.php` for WordPress; `.git/`) is world-readable or
   readable by a group that is not the site's own group.
4. The pool socket (generated or given) has owner = site user, group = agensio's group,
   mode 0660 or stricter, and its directory is not writable by other users.
5. No two sites with different users name the same socket, root, state directory or log
   file.
6. Log files and their directories: see below; a log file readable by a different site
   user is refused.

Sites without `user` are not checked (single-tenant machines stay as they are). A
`[server] strict_users = true` makes `user` mandatory on every site, for hosting
setups where an unlabelled site is a mistake.

The checks are `stat()` calls at load time, nothing on the request path.

## Per-site logs

`access_log` and the error log of a site with `user` are opened at startup and the file
is made `<user>:<agensio group> 0640`: the customer reads it, agensio writes it
(through the group), others nothing. This needs either root at startup (H2, not yet)
or `CAP_CHOWN`; without either, agensio keeps the file as its own user, mode 0640, and
prints a warning naming the site, so the customer's read access is the only thing lost.
The log directory itself must be `0750` owned by agensio and not writable by any site
user (rule 6), so a customer cannot plant a symlink where agensio will write.

## What this does not protect

The web server process still reads every site's docroot: agensio runs as one user and
must serve all static files. A vulnerability in agensio itself therefore still exposes
every site's files; that is H3b's job (Landlock, `openat2`). The model here matches
ISPConfig: PHP isolated per customer, the web server shared and trusted.

## Tests

- Unit: the pool generator (golden files for the Laravel, WordPress, php presets and
  the `extra` passthrough), socket path derivation, sharing rules between sites, and
  every validation rule against a fake `stat` table (owner, group, mode combinations).
- Integration, Linux only, in a root devbox container (`tests/pools.sh`): create users
  `web1` and `web2`, generate pools for two sites, start the distro php-fpm with them,
  run agensio as user `agensio`, and check: each site's script runs as its own user
  (`/info` route prints uid), `open_basedir` blocks reading the other site's root,
  session files land in the private directory, a world-readable `.env` is refused by
  `-t`, a socket with the wrong group is refused by `-t`.
- The A/B gate: nothing on the request path changes (only `keep_conn` defaults for
  generated pools), so the static numbers must be identical; the Laravel bed run with a
  generated pool must match the unix-socket row of C3a.

## Steps

1. C3b-1 Config keys, pool generation, `agensio pools`, `--explain` output, unit tests.
2. C3b-2 Validation rules with unit tests, then the Linux integration test.
3. C3b-3 Per-site log ownership (with the warning path when not root).
4. Docs: `docs/configuration.md` section "Hosting: one user per site", the example

Estimated size: about 600 lines of C++ (config, generator, validation), 300 lines of
tests, one shell integration test. No new dependencies.

## Questions for the owner

1. Generation model: agensio writes pool files for the distro's php-fpm master (this
   proposal) versus agensio spawning and supervising one php-fpm master per site. The
   first fits packaging and panels; the second gives per-site restarts and cgroups but
   makes agensio a process supervisor. Proposal: the first now, the second as an option
   later if the control API needs restarts.
2. Socket permission model: socket group = agensio's group, mode 0660 (this proposal)
   versus agensio being added to every site's group. The first needs no membership
   management; the second lets the socket stay `0660 web1:client1`. Proposal: the first.
3. Should H2 (start as root, bind, drop privileges) be pulled forward into this step? Log
   ownership and privileged ports both want it, and it is about 100 lines. Proposal:
   yes, as C3b-3, because per-site logs are half-done without it.
4. Pool directory and php version detection: Debian/Ubuntu (`/etc/php/X/fpm/pool.d`),
   RHEL/Fedora (`/etc/php-fpm.d`, one version), Alpine (`/etc/php8X/php-fpm.d`),
   macOS brew (`/opt/homebrew/etc/php/X/php-fpm.d`). Proposal: detect those four and
   require `[server] pools` elsewhere.
5. `pm = static` for generated pools (predictable, what the benchmarks use) versus
   `pm = dynamic`/`ondemand` (what panels default to for many small sites). Proposal:
   `pm = "static" | "dynamic" | "ondemand"` under `php`, default static with
   `children`, dynamic taking `children` as max.

# Agensio needs conformance fixes before features

A general-purpose web server is feature complete for a version 1.0 in November 2026 when five things hold together: it meets the MUST-level rules of RFC 9110, 9112, 9113, 9114 and 9000 to 9002 and refuses ambiguous messages instead of repairing them; it ships the floor every established server shares; it renews certificates unattended under 45-day and 6-day lifetimes; it hosts the mainstream PHP and proxied applications from their own documentation; and it carries a written stability, security and maintenance promise that outsiders have verified. agensio at 0.1.0-alpha.145 already holds most of the second, third and fourth: three protocol stacks of its own, compression in three codings, per-site users and PHP pools, presets, typed redirects and header rules, ACME, graceful reload with site isolation, and a role-checked control API with an MCP server that no established server matches. The four code audits (made by reading the source at `bf67e7ac`, not by running it) find the protocol cores sound, **52 of 69 examined RFC 9112 requirements, 78 of 109 for RFC 9113 and 70 of 107 for RFC 9000 fully met**, and list 121 rows of partly met or unmet requirements, most of them edges no well-behaved client reaches. The rows that matter are few and concrete: `If-Match` and `If-Unmodified-Since` are never evaluated, the absolute-form request target is refused, only seven methods ever reach an application (so WebDAV, CalDAV and the new QUERY method cannot work), HTTP/2 receive-window credit leaks on unread bodies, a stop cuts HTTP/1 and HTTP/2 requests without GOAWAY or drain, HTTP/3 has two buffers a client can grow without bound, two accounting gaps and NewReno without pacing, and TLS policy is whatever OpenSSL's defaults are. One finding, unvalidated pseudo-header values in HTTP/2 and HTTP/3 requests, was reproduced live on 2026-11-13 and is fixed in the working tree for 0.1.0-alpha.146. Against the established servers the missing features are a short list (custom error pages, directory listing, capture-style rewrites, wildcard names, TLS policy keys, ARI and a second ACME challenge, internal redirect for protected downloads). What is least developed is not a feature at all: there is no security policy file, no written definition of "stable", no configuration freeze, no independent audit and no row in the public QUIC interop matrix, and every comparable project needed months of frozen-feature exposure before the label.

## How to read the evidence in this report

Two kinds of evidence appear and are kept apart. **Web research** (six notes files, collected 2026-11-13) describes the standards, the other servers, administrators, applications and release practice; it is cited with links. **Code audits** (four notes files) describe agensio and are cited as `file:line` at commit `bf67e7ac` (0.1.0-alpha.145) with the auditor's confidence. The audits were read-only: nothing was built, run, fuzzed or sent over a socket, so every audit row is a reading of a code path, and where the effect on a real peer is less certain than the reading the row says so. The TLS audit additionally quoted RFC section numbers other than RFC 9001 and RFC 6797 from memory and OpenSSL's defaults from memory; both need checking before they are cited elsewhere.

## The RFC core is small; the 2025–2026 security consensus raised the bar

### HTTP semantics, HTTP/1.1 and what remains of HTTP/1.0

The conformance core of HTTP/1.x is narrow: GET and HEAD, strict message framing, one `Host`, the absolute-form request target, `Date`, the conditional requests an origin evaluates, and correct `Expect` and 1xx behaviour. RFC 9112 says it without qualification: **"A server MUST accept the absolute-form in requests even though most HTTP/1.1 clients will only send the absolute-form to a proxy"** ([RFC 9112](https://www.rfc-editor.org/rfc/rfc9112.html)). HTTP/1.0 has no normative document of its own any more (RFC 1945 is informational); what binds a server is what RFC 9110 and 9112 say about 1.0 peers: no chunked coding and no 100 Continue to a 1.0 client, persistence only on `Connection: keep-alive`, a request without `Host` accepted, `Transfer-Encoding` from a 1.0 sender treated as faulty framing ([RFC 9112](https://www.rfc-editor.org/rfc/rfc9112.html)). Almost everything else in RFC 9110 (multiple ranges, content negotiation, TRACE, CONNECT, trailers, digest authentication, caching) is optional.

The standards barely moved in 2024 to 2026, the security consensus did. PortSwigger's August 2025 research argues that HTTP/1.1 between proxies and origins cannot be made safe by parser fixes: "Requests are simply concatenated on the underlying TCP/TLS socket with no delimiters, and there are multiple ways to specify their length", and its headline defence is HTTP/2 to origins ([PortSwigger](https://portswigger.net/research/http1-must-die)). The same paper names "static files on nginx", any path where the back end answers before it has read the body, as the gadget that turns a harmless discrepancy into an attack, and found Apache hard to exploit "because it closes connections on error". The 2025 "funky chunks" work turned lenient line endings in chunked framing into CVEs in Go, Netty, Jetty and Kestrel ([Go GO-2025-3563](https://pkg.go.dev/vuln/GO-2025-3563)); nginx 1.29.4 made a bare LF in a chunked body an error and began validating host and port per RFC 3986 ([nginx CHANGES](https://nginx.org/en/CHANGES)), and the RFC Editor rejected an erratum that would have allowed bare LF there ([RFC 9112 errata](https://errata.rfc-editor.org/search/?rfc_number=9112)). The direction of every fix is reject and close, never repair.

Three RFCs published since mid-2025 touch a server directly. RFC 9931 (March 2026) updates RFC 9112 for rejected CONNECT and Upgrade ([RFC 9931](https://www.rfc-editor.org/rfc/rfc9931.html)). **RFC 10008 (June 2026) defines the QUERY method**, safe and idempotent with a body, which a server and its FastCGI and proxy paths must be able to pass ([RFC 10008](https://www.rfc-editor.org/rfc/rfc10008.html)). RFC 10036 (August 2026) defines `Incremental: ?1`: an intermediary "SHOULD NOT buffer the entire message before forwarding it" and one that refuses "MUST generate an error response rather than buffering" ([RFC 10036](https://www.rfc-editor.org/rfc/rfc10036.html)); Caddy 2.11.7 already implements it ([Caddy reverse_proxy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy)). On the proxy side the competitive baseline is what nginx added in eighteen months: trailers pass-through (1.27.2), 103 Early Hints from backends (1.29.0), HTTP/2 to backends (1.29.4), keep-alive to upstreams by default (1.29.7), a header-count limit (1.29.8) ([nginx CHANGES](https://nginx.org/en/CHANGES)).

### HTTP/2: push and the priority tree are dead, the denial-of-service budgets are the requirement

RFC 9113 deprecates the RFC 7540 priority tree and the `Upgrade: h2c` path, keeps prior-knowledge h2c, forbids connection-specific fields, and in section 10.5 tells implementations to bound SETTINGS, PING, empty frames, small WINDOW_UPDATEs and field-block size ([RFC 9113](https://www.rfc-editor.org/rfc/rfc9113.html)). Server push is finished in practice: Chrome disabled it in version 106 ([Chrome for Developers](https://developer.chrome.com/blog/removing-push)) and nginx removed its implementation in 2023. The replacement for priorities is RFC 9218 (urgency and incremental in a `Priority` field and PRIORITY_UPDATE frames), which **nginx adopted for HTTP/2 as late as 1.31.7 on 14 October 2026**, ignoring RFC 7540 signals from then on ([RFC 9218](https://www.rfc-editor.org/rfc/rfc9218), [nginx CHANGES](https://nginx.org/en/CHANGES)).

What a 2026 server must get right is work done for streams the protocol no longer counts. Rapid Reset (CVE-2023-44487) was exploited in the wild with reported peaks of 398 million requests per second ([CISA](https://www.cisa.gov/news-events/alerts/2023/10/10/http2-rapid-reset-vulnerability-cve-2023-44487)); the CONTINUATION flood of April 2024 exhausted memory or CPU from one connection in Apache httpd, Envoy, Go and others ([CERT/CC VU#421644](https://kb.cert.org/vuls/id/421644)); MadeYouReset (CVE-2025-8671, August 2025) provokes resets the server itself sends, so the stream stops counting against the concurrency limit while the back end keeps working ([CERT/CC VU#767506](https://kb.cert.org/vuls/id/767506)). The implementations that were not affected by MadeYouReset count streams they are still working on whatever the protocol state says. Conformance suites do not test any of this; h2spec† predates RFC 9113.

### HTTP/3 and QUIC: a fifth of requests, a narrow required core

HTTP/3 carries about a fifth of requests (**21 % of requests to Cloudflare in 2025, HTTP/2 50 %, HTTP/1.x 29 %**, unchanged from 2024) and is offered by about 40 % of websites ([Cloudflare Radar 2025](https://blog.cloudflare.com/radar-2025-year-in-review/), [W3Techs](https://w3techs.com/technologies/breakdown/ce-http3/dns_server)). The required core is QUIC version 1 with Retry, stateless reset, the amplification limit, path validation for NAT rebinding, connection-id management, key update, QPACK, GOAWAY and an `Alt-Svc` advertisement. The practical competitive bar is lower than it looks: nginx's HTTP/3 module is still documented as experimental and is not built by default ([nginx HTTP/3 module](https://nginx.org/en/docs/http/ngx_http_v3_module.html)), no released Apache httpd has HTTP/3, and h2o's is labelled experimental. nginx did move from NewReno to CUBIC in 1.27.5 and added 0-RTT with OpenSSL 3.5.1 in 1.29.1 ([nginx CHANGES](https://nginx.org/en/CHANGES)). QUIC version 2, datagrams, extended CONNECT over HTTP/3 (no browser ships WebSocket over HTTP/3), WebTransport, multipath (RFC 10069, this month) and qlog are optional or emerging. The QUIC community's shared definition of "interoperable" is the interop runner's fourteen cases, among them `retry`, `resumption`, `zerortt`, `keyupdate`, `rebind-port`, `rebind-addr`, `v2` and `connectionmigration`, where an unsupported case exits 127 ([interop runner test cases](https://github.com/quic-interop/quic-interop-runner/blob/master/quic.md)).

The most concrete 2026 lesson for an own HTTP/3 stack is the QPACK "header accordion" published on 20 October 2026: **7 of 10 tested implementations** could be made to expand a small HEADERS frame into a very large decoded field section, and the stated fix is a running total of decoded size including the 32-byte per-field overhead, enforced during decoding ([FoxIO write-up, translation](https://lilting.ch/en/articles/http3-qpack-header-amplification)).

### HTTP/2: the codec is clean, the edges of windows, GOAWAY and stream state are not

The HPACK codec has no gap the audit could find, and the frame layer is in good shape. The h2spec result the design quotes (146 of 146 over TLS, 145 of 146 plain) was not re-run, and h2spec covers few of the rows below.

**Pseudo-header values: confirmed live and fixed in the working tree.** At `bf67e7ac` the request assembler shared by HTTP/2 and HTTP/3 returned for a pseudo-header before the field-value rules ran, so the values of `:path` and `:authority` were not checked for characters a request target and a host must not contain before the request was routed and, on a proxy location, written into the HTTP/1.1 head sent to the origin (RFC 9113 8.2.1 and 10.3, RFC 9114 4.1.2 and 10.3; audit_http2 row 1, audit_http3 row 4; `src/http/request_assembly.hpp:41-50`, `src/handlers/proxy.cpp:108, 236`). The rule now applied for 0.1.0-alpha.146 (unreleased): each pseudo-header value is checked once per table entry, `:path` as a request target without whitespace or control characters, `:authority` by the Host rules, `:method` as a token and `:scheme` as a scheme, and a request that fails is malformed and reset (`src/http/request_assembly.hpp:47-60` in the working tree, with `tests/pseudo-header-bytes.py`; own check).

## TLS and certificates: lifetimes and library defaults moved, agensio sets four things

### What the baseline is in late 2026

The baseline is TLS 1.3 plus TLS 1.2 with ECDHE AEAD suites only, client-chosen cipher order, and the hybrid group X25519MLKEM768 first. TLS 1.3 was republished as RFC 9846 in July 2026, backward compatible ([RFC 9846](https://www.rfc-editor.org/rfc/rfc9846.html)). BCP 195 says a server MUST NOT negotiate TLS 1.0 or 1.1, SHOULD NOT negotiate static RSA or finite-field DHE in TLS 1.2, **MUST rotate ticket-encryption keys regularly ("e.g., weekly")**, MUST support SNI and ALPN, and when no ALPN protocol matches "SHALL respond with a fatal" `no_application_protocol` alert ([RFC 9325](https://www.rfc-editor.org/rfc/rfc9325.html)). The reference profiles administrators and generators know moved to docs.tlsref.org; version 6.0 keeps two, Modern (TLS 1.3 only) and Intermediate (TLS 1.2 and 1.3 with six ECDHE AEAD suites), both with groups X25519MLKEM768, X25519, prime256v1, secp384r1 in that order and the client choosing the cipher, and it no longer mentions OCSP stapling at all ([TLSRef server-side TLS](https://docs.tlsref.org/server-side-tls.html)). SSL Labs caps a server without TLS 1.3 at A- ‡ ([Qualys notice](https://notifications.qualys.com/product/2025/02/26/key-changes-in-ssl-labs-grading-and-qualys-certview)).

Post-quantum key exchange is deployed, not emerging: the majority of human-initiated traffic to Cloudflare used it by late October 2025, and OpenSSL 3.5 changed its default group list "to include and prefer hybrid PQC KEM groups" ([Cloudflare](https://blog.cloudflare.com/pq-2025), [OpenSSL 3.5 notes](https://openssl-library.org/news/openssl-3.5-notes/)). A server needs only to leave that default alone and to read a ClientHello that no longer fits one packet. Encrypted Client Hello became RFC 9849 in March 2026, but the OpenSSL implementation arrived with 4.0, which is not an LTS, and supports shared mode only ([OpenSSL on ECH](https://openssl-library.org/post/2026-03-11-ech/)); nginx 1.29.4 needed OpenSSL's ECH branch for it ([nginx on ECH](https://blog.nginx.org/blog/encrypted-client-hello-comes-to-nginx)). It is optional for a 1.0.

Certificates changed more than the protocol. Let's Encrypt removed the OCSP URL from its certificates on 7 May 2025 and now issues 45-day certificates on the opt-in `tlsserver` profile; the default profile goes to 64 days on 10 February 2027 and **45 days on 16 February 2028, with a 7-hour authorization reuse period**, so every renewal then performs a fresh validation ([Let's Encrypt upcoming features](https://letsencrypt.org/upcoming-features), [From 90 to 45](https://letsencrypt.org/2025/12/02/from-90-to-45)). Its guidance to clients is to use ACME Renewal Information (ARI, RFC 9773), otherwise to renew at about two thirds of the lifetime, and it warns that "a hardcoded interval of 60 days will no longer be sufficient". ARI renewals are "exempt from all rate limits"; the limits themselves include 5 authorization failures per identifier per account per hour, a pause after 1,152 consecutive failures, and a `Retry-After` on every rate-limit error ([Let's Encrypt rate limits](https://letsencrypt.org/docs/rate-limits/)). nginx's own ACME module, a year old, already has HTTP-01 and TLS-ALPN-01, ARI, IP identifiers, profiles and external account binding, and no DNS-01 ([nginx-acme](https://github.com/nginx/nginx-acme)). OCSP stapling is therefore a low-value option in 2026, and HSTS `preload` must stay an explicit opt-in: "Software and projects that offer HSTS configuration or HTTPS advice should not include `preload` by default" ([hstspreload.org](https://hstspreload.org/)). On-demand issuance is a known abuse path that Let's Encrypt began blocking in February 2026 ([Let's Encrypt community](https://community.letsencrypt.org/t/blocking-some-on-demand-issuance-caused-by-internet-scanning/245553)).

## What the established servers ship: a small universal floor, and agensio is short five items of it

nginx serves 30.0 % of websites whose server is known, Apache 20.9 %, LiteSpeed 13.4 % and Caddy 1.2 % ([W3Techs, 13 November 2026](https://w3techs.com/technologies/overview/web_server)). Five things are universal across every server that serves sites directly (nginx, Apache, Caddy, LiteSpeed and OpenLiteSpeed, h2o) and form the hard floor: name-based virtual hosts with TLS and HTTP/2; static serving with index, fallback, error pages, Range, conditional requests and compression; FastCGI to PHP; a reverse proxy with WebSocket and timeouts; and a reload that drops nothing plus a configuration test. One level up is where they divide and where users argue: automatic certificates, a response cache for PHP, per-address rate limiting, active health checks and `.htaccess`.

The baseline moved in 2025 and 2026 because open-source nginx absorbed a list of former commercial features: DNS re-resolution of upstream names (1.27.3), Early Hints (1.29.0), HTTP/2 to backends (1.29.4), sticky sessions (1.29.6), upstream keep-alive by default (1.29.7), `least_time` (1.31.0), an ACME module, and a control API that can inspect and reload (1.31.5, behind a build flag) ([nginx upstream module](https://nginx.org/en/docs/http/ngx_http_upstream_module.html), [nginx CHANGES](https://nginx.org/en/CHANGES), [NGINX blog on 1.31.5](https://blog.nginx.org/?p=75128)). Still commercial-only on nginx.org's own pages are active health checks, the statistics API, cache purge, upstream `queue` and `slow_start` ([nginx health checks](https://nginx.org/en/docs/http/ngx_http_upstream_hc_module.html), [nginx proxy module](https://nginx.org/en/docs/http/ngx_http_proxy_module.html)). "Free nginx lacks X" is a shrinking argument.

Every server also has a deliberate hole that the market tolerates as long as there is a documented way around it: nginx reads no `.htaccess`; Caddy's standard build has no rate limiting and no response cache, and forum requests to make rate limiting a default module run from 2020 to today ([Caddy forum](https://caddy.community/t/adding-rate-limiting-as-a-default-module/23871)); OpenLiteSpeed reads `.htaccess` only at start and has no ESI ([OpenLiteSpeed](https://openlitespeed.org/?p=8058)); h2o stopped tagging releases in 2019 and is under 0.1 % of sites despite its benchmarks ([h2o releases](https://github.com/h2o/h2o/releases)). Performance alone does not create adoption; release cadence, packaging and documentation do.

The lesson cuts both ways: six years later that omission is still the first line of every comparison.

## What administrators ask for: the floor is certificates, explanation and visibility

**A caveat on the ranking.** The administrator research could not read Server Fault, Stack Overflow or Reddit; direct fetches, the Stack Exchange API and domain-limited searches were all refused. The ranking below is therefore the researcher's judgement from GitHub issue lists in thumbs-up order (nginx, Caddy, Traefik, OpenLiteSpeed), the Caddy and nginx forums' top topics of the year, and Hacker News, whose points and comment counts are exact. GitHub reaction counts were not in the fetched pages, only the order. The researcher expects the classic question-and-answer topics (configuration traps, PHP hand-off errors, behaviour behind a proxy) to be under-evidenced rather than over-ranked. Quotations in those notes were extracted by a summarising tool, so this report paraphrases them.

Where counts could be read, attention in 2025 and 2026 went to certificates, security and ease. "Nginx introduces native support for ACME protocol" is the top nginx story on Hacker News since January 2025 with **810 points and 298 comments**; "New Nginx Exploit" follows with 444 points; the Caddy thread of February 2025 has 568 ([HN on nginx ACME](https://news.ycombinator.com/item?id=44889941), [HN on the nginx exploit](https://news.ycombinator.com/item?id=48138268), [HN on Caddy](https://news.ycombinator.com/item?id=43070025)). nginx shipped eight security releases between February and October 2026, and the fixes reached configuration-evaluation code (the rewrite module, `map` with regular expressions, `alias`), which an administrator cannot avoid by turning a protocol off ([nginx 2026 news](https://nginx.org/2026.html)). Among PHP teams, Caddy's use rose from 11 % to 21 % in one survey year, with nginx at 69 % and Apache at 58 % ([heise on Zend's PHP Landscape Report](https://heise.de/-11267214)). PHP pain is absent from the servers' own trackers; it lives in question-and-answer sites and application forums, which is the gap a PHP-first server fills.

A C++ server arriving in the year of nginx's advisories will be asked the memory-safety question directly.

Most applications need no regular expression once a server has a front-controller fallback, an entry-point whitelist, path info and glob-style refusals: Laravel, Symfony, CodeIgniter, CakePHP, Yii, Matomo, Moodle, Kanboard, Grav, MediaWiki and Drupal use regex syntax in their nginx files only for things a prefix, an exact match, a suffix or a name pattern states equally. The real exceptions are few and specific. WordPress multisite in subdirectory mode needs the first path segment removed before `wp-*` paths and any `.php`; subdomain mode needs only a wildcard server name. The file-based page caches (WP Super Cache, W3 Total Cache, Statamic's full measure) need a `try_files` target assembled from host, path and query string with method and cookie conditions, though each also works with PHP serving the cached file ([WordPress nginx page](https://developer.wordpress.org/advanced-administration/server/web-server/nginx/), [Statamic static caching](https://statamic.dev/static-caching)). PrestaShop's product-image URLs and Magento's versioned static path with its `static.php` and `get.php` fallbacks need capture and substitute ([PrestaShop 9](https://devdocs.prestashop-project.org/9/basics/installation/advanced/nginx/), [Magento sample](https://raw.githubusercontent.com/magento/magento2/2.4-develop/nginx.conf.sample)). **Magento and PrestaShop are therefore the two mainstream applications a server limited to prefix, exact and suffix locations and `try_files` cannot host from their official configuration.** The applications researcher's inference is that five typed primitives close almost all of the gap without a regex engine: strip one leading path segment, a `try_files` target built from host, path and query with conditions, a fallback that carries the request path as path info or one query parameter, removal of a variable segment of a simple class, and prefix stripping for proxies. agensio has none of the first four today and wildcard names are not routed, so WordPress multisite cannot be hosted in either mode.

On presets, the two panels examined both cover WordPress, Laravel, Drupal, Joomla, Magento, PrestaShop, Symfony, Moodle and CodeIgniter ([HestiaCP templates](https://github.com/hestiacp/hestiacp/tree/main/install/deb/templates/web/nginx/php-fpm), [CloudPanel templates](https://github.com/cloudpanel-io/vhost-templates/tree/master/v2)); both listings may be truncated, and no source ranks which templates users request most. agensio has `laravel`, `drupal`, `wordpress`, `grav`, `php`, `static`, `proxy`, `rails`, `redmine`, `django`, `wagtail` and `node`; the roadmap names `symfony`, `joomla`, `phpbb`, `nextcloud` and `mediawiki` as the next rows, and for an application without a preset the documented way is its official server configuration translated into `rules` on `app = "php"` and checked with `path_check`. For proxied applications the valuable preset is small and the same everywhere, and each project keeps a community list of proxy examples (Vaultwarden's wiki, Uptime Kuma's wiki, the Gitea, Forgejo, Synapse and Jellyfin documentation) where a new server's snippet can be contributed.

## Beyond features: "stable" is a written promise that outsiders have checked

No comparable project reached "stable" on features alone. Each either had years of production traffic behind the label (HAProxy, nginx, Pingora inside Cloudflare, WireGuard) or ran a named beta and release-candidate programme in which users were asked to deploy to production. Caddy 2 ran betas from September 2019, declared itself feature-complete at beta 18, and defined its release candidates this way: "Release candidates are production-ready but it means we are reserving another cycle for last-minute bug fixes" ([Caddy 2 RC1](https://caddy.community/t/caddy-2-release-candidate-1/7415)); general availability followed on 4 May 2020. Traefik 3 took from a first beta in December 2022 to April 2024 ([Traefik 3.0 beta programme](https://traefik.io/blog/traefik-proxy-3-0-scope-beta-program-and-the-first-feature-drop)). HAProxy encodes the rule in its branch policy: a point-zero long-term release has already had about six months of stabilisation in the preceding development-status branch, so "it is much safer to use even just after it is released", and odd branches "MUST ABSOLUTELY NOT BE PACKAGED BY OPERATING SYSTEM VENDORS" ([HAProxy BRANCHES](https://raw.githubusercontent.com/haproxy/haproxy/master/BRANCHES)). Envoy defines stable as any version released in the last twelve months, with a stated class of fixes that is backported ([Envoy RELEASES.md](https://raw.githubusercontent.com/envoyproxy/envoy/main/RELEASES.md)).

The most common regret is a 1.0 whose configuration then had to be broken: Caddy 1.0 was announced on the same day as its incompatible successor, and its short end of life drew a long thread of objections ([Caddy v1 end of life](https://caddy.community/t/caddy-version-1-end-of-life-date/7835)). The label binds the configuration format and the command line more than the code. The second lesson is specific to a server that ships a young protocol stack: freenginx forked in February 2024 after CVEs and a security release were issued for bugs in nginx's experimental HTTP/3 code over a core developer's objection ([The Register](https://www.theregister.com/2024/02/16/freenginx_fork/)). If HTTP/3 is in a 1.0, it is in the security-support scope; if it is not ready for that, the security policy has to say so before the label. Nobody was criticised for labelling late: Pingora is still 0.x after years of production use ([Cloudflare](https://blog.cloudflare.com/pingora-open-source)).

For network-facing C++ the expected assurance in 2026 has four parts. The first is published hardened build flags; the OpenSSF guide dated 20 August 2026 recommends, among others, `-D_FORTIFY_SOURCE=3`, `-D_GLIBCXX_ASSERTIONS`, `-fstack-clash-protection`, `-fstack-protector-strong`, `-fstrict-flex-arrays=3`, `-fcf-protection=full`, `-ftrivial-auto-var-init=zero`, full RELRO and PIE, each with a stated cost ([OpenSSF hardening guide](https://best.openssf.org/Compiler-Hardening-Guides/Compiler-Options-Hardening-Guide-for-C-and-C++)). The second is continuous coverage-guided fuzzing with sanitizers; OSS-Fuzz accepts projects that "have a significant user base and/or be critical to the global IT infrastructure" ([OSS-Fuzz](https://google.github.io/oss-fuzz/getting-started/accepting-new-projects/)), while the OpenSSF Scorecard's fuzzing check is equally satisfied by ClusterFuzzLite in the project's own CI ([Scorecard checks](https://github.com/ossf/scorecard/blob/main/docs/checks.md)). The third is an independent audit with a public report: X41 D-Sec audited ngtcp2 and nghttp3 in **25 person-days** with the IETF documents as the reference threat model ([X41 D-Sec](https://x41-dsec.de/security/research/job/news/2025/05/22/nghttp3-ngtcp2)), and OSTIF's publications put a managed engagement at about USD 74,000 on average ‡ ([OSTIF annual report](https://ostif.org/wp-content/uploads/2025/02/2024-OSTIF-Annual-Report.pdf)); an own QUIC, QPACK, HTTP/2, HTTP/1 parser, TLS stream and root helper is several times the surface of those two libraries. The fourth is a written answer to the memory-safety question, because government guidance names network-facing C and C++ as the priority case ([CISA](https://www.cisa.gov/resources-tools/resources/memory-safe-languages-reducing-vulnerabilities-modern-software-development)).

Vulnerability handling has a low entry cost. The OpenSSF Best Practices "passing" level requires a published reporting process and an initial response within 14 days ([Best Practices criteria](https://www.bestpractices.dev/en/criteria/0)); GitHub acts as a CVE Numbering Authority for projects it hosts, so a repository security advisory with "Request CVE" is a sufficient route ([GitHub docs](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/fix-reported-vulnerabilities/publishing-a-repository-security-advisory)). Paid bounties are no longer a realistic channel: curl ended its bounty on 31 January 2026 after the confirmed rate of reports fell from above 15 % to below 5 % ([curl](https://daniel.haxx.se/blog/2026/01/26/the-end-of-the-curl-bug-bounty/)). Under the EU Cyber Resilience Act a solo, non-monetised MIT project is outside scope: it is not a manufacturer unless the software is supplied in the course of a commercial activity, and a steward is defined as a legal person ([OpenSSF CRA guide](https://best.openssf.org/CRA-Brief-Guide-for-OSS-Developers), [OpenSSF stewards one-pager](https://policy.openssf.org/CRA/stewards-one-pager.html)). That reading rests on OpenSSF and law-firm summaries, not on the regulation's text, and is not legal advice; selling the server, a paid edition or support priced above cost changes it. The Act still shapes a 1.0 indirectly, because any EU company that ships the server inside a product must do due diligence on it and will look for a vulnerability policy, a supported-versions statement and a software bill of materials.

Third-party verification is where a young server earns belief. The public QUIC interop matrix is produced by someone else's infrastructure and updated several times a day ([interop results](https://interop.seemann.io/)); TechEmpower's benchmarks were archived on 24 March 2026, so benchmark claims are now judged on method alone ([TechEmpower](https://github.com/TechEmpower/FrameworkBenchmarks/issues/10932)). For AI-assisted code the 2026 norm is disclosure plus human accountability: a May 2026 study found 78 % of written project AI policies allow such contributions and 51 % require disclosure ([arXiv 2605.16706](https://arxiv.org/abs/2605.16706)), and the reference case for what happens otherwise is a framework announced as almost entirely AI-written that had seven vulnerabilities disclosed by a competitor within about a week ‡ ([OfficeChai](https://officechai.com/ai/after-cloudflare-created-vercels-next-js-in-a-week-using-ai-vercel-discloses-7-bugs-in-the-new-framework)). What shifts the judgement is external and checkable: an audit report, public fuzzing with coverage numbers, the interop matrix, differential-testing results, and a plain statement of how AI was used and who answers for each change.

- A continuity statement and a statement on AI-assisted development and review: release_readiness_criteria.md section 5; administrator_needs_complaints.md trust section.
- The OpenSSF Best Practices passing badge, and a published Scorecard with notes on the solo-maintainer checks: release_readiness_criteria.md section 2.
- Close the roadmap's open checkpoints that need only a record: a browser's HTTP/3 connection, control traffic measured beside a data-plane load: ROADMAP I and F checkpoints.

### 6. Candidates to leave until after 1.0, with the reason

- 0-RTT over TLS and QUIC: replayable, needs the RFC 8470 profile, opt-in in every server: http_standards_landscape.md section 4; tls_certificates_landscape.md section 1.
- Encrypted Client Hello: needs OpenSSL 4.x, which is not an LTS: tls_certificates_landscape.md section 3.
- NEW_TOKEN, ECN, active migration, QUIC version 2, multipath, datagrams, qlog: optional or emerging, and the interop runner lets a server decline them: http_standards_landscape.md section 4; audit_http3_quic.md Table 2.
- WebSocket over HTTP/2 and over HTTP/3: nginx has neither, no browser ships the HTTP/3 form, and absence costs a connection, not correctness: http_standards_landscape.md sections 3 and 6.
- HTTP/3 to origins and gRPC proxying: experimental everywhere for the first; the second needs HTTP/2 upstream and trailers end to end: http_standards_landscape.md section 6.
- A response cache for PHP and proxied answers: Caddy and h2o ship none in core and plugins can serve through PHP, but it is the feature WordPress hosts rely on, so the position must be stated: server_feature_matrix.md sections 0 and 3; administrator_needs_complaints.md catalogue item 18.
- Per-address request limiting inside the server: decided on 2026-10-02 to be the firewall's and fail2ban's; Apache's and Caddy's cores lack it too, and reviewers will list it: server_feature_matrix.md section 5; administrator_needs_complaints.md catalogue item 5; ROADMAP H4.
- Active health checks, sticky sessions, further balancing algorithms: a hosting site has one local origin: server_feature_matrix.md section 4; administrator_needs_complaints.md catalogue item 14.
- OCSP stapling: Let's Encrypt ended OCSP and the reference profile dropped it: tls_certificates_landscape.md section 4.
- DNS-PERSIST-01: the draft changed format between versions and Let's Encrypt does not offer it yet: tls_certificates_landscape.md section 5.
- Post-quantum certificates and two certificates per name: no public CA issues the former: tls_certificates_landscape.md sections 2 and 4.
- On-demand certificate issuance: an abuse path, and a hosting server knows its site list: tls_certificates_landscape.md section 5.
- Multiple ranges, trailer pass-through, content negotiation, Digest, TRACE, forward-proxy CONNECT, SSI, a WebDAV file server, image filters, SCGI and uwsgi: niche for this audience, and the RFC allows their absence: server_feature_matrix.md section 0; audit_http1_semantics.md Table 2.
- `.htaccess` emulation: nginx reached 30 % without it; the answer is a migration path: server_feature_matrix.md section 2; administrator_needs_complaints.md catalogue item 17.
- A web UI: the demand is real among small operators, but the agent interface covers the same job: administrator_needs_complaints.md catalogue items 15 and 16.
- Windows and macOS as supported production platforms: one request found in two years: administrator_needs_complaints.md catalogue item 19.
- Kernel-enforced containment of the server itself: no source showed a mainstream server applying Landlock or seccomp to itself; unit hardening is the common practice: ROADMAP H3b; release_readiness_criteria.md section 2 gaps.
- kTLS, io_uring, release folders, one process per site user, a reset key that survives restarts: performance or later designs the owner has already parked: ROADMAP "Later / ideas"; audit_http3_quic.md notes.
- Compression dictionaries, resumable uploads, message signatures: emerging, application-level or Chromium-driven: http_standards_landscape.md section 1.
- A paid bug bounty and OSS-Fuzz enrolment: the first buys triage load in 2026, the second is likely declined until distributions carry the server: release_readiness_criteria.md sections 2 and 6.

## Conclusion

The audits show one pattern more than any single defect: agensio is careful about bytes it intends to use and loose about bytes it has decided not to use. The HTTP/2 window that is not returned for an unread body, the QUIC credit not returned for an abandoned stream, the HEADERS frame stored after its 431, the CRYPTO data kept after the handshake, the close sent before a rejected upload has been read: each is a discard path, and discard paths are what conformance suites skip and what the 2025 desynchronisation research and the 2026 header-accordion disclosure both exploited in other servers. A review organised around "what happens to input after the answer is decided" would find the remaining members of the family faster than another pass through the RFCs section by section. The second pattern is that the design documents run ahead of the code in nearly twenty places, which matters because an outside auditor will take the threat tables as claims.

The other finding is about order. agensio's breadth already exceeds what Caddy 2 or any recent entrant shipped at first stable, and the gaps against the incumbents are short lists. The long pole is elsewhere: every comparable project spent about six months with a frozen feature set in other people's production before the label, and that clock cannot start while configuration keys still change without compatibility. The decision that moves the 1.0 date most is therefore not which feature to add but when to stop adding, write the promise down, and invite the outside checks (the public interop matrix, a differential HTTP/1 run, an audit) that turn a list of unit tests into evidence a stranger accepts.

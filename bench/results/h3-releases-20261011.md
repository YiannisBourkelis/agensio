# HTTP/3 at 64 streams across the releases, alpha.23 to alpha.69 (2026-10-11)

Why: the HttpArena lite comparison (`httparena-lite-20261011-alpha23-vs-alpha69.md`) and the
A/B `ab-20261011-145717.md` (three rounds) read the h3 row with 64 streams per connection 1.07
dearer on alpha.69 than on alpha.23; this looks for the release that did it.

- machine: AMD Ryzen 9 9900X (12 cores, 24 threads), Debian 13, kernel 6.12.111+deb13-amd64, the
  `agensio-devbox` container (h2load with QUIC, `/opt/nghttp2/bin/h2load`)
- the row of `bench/ab.sh -3` "h3:/:64:64" measured the way ab.sh measures it (its
  `bench/tmp/ab-agensio-h3.toml`, one worker, a warm-up request, `h2load --alpn-list=h3 -D 5 -c64
  -m64 -t4`, server CPU time over the requests done), each binary built as ab.sh builds a base
  (Release, no tests, `bench/tmp/ab/<commit>`), rotated through the rounds in one session, each
  round starting one binary later: `bench/h3/releases.sh`

| release | median us/req | range | median / alpha.23 |

No release made the row dearer: every median is within 3 % of alpha.23's, with no step between
two releases, and head to head over ten rounds alpha.69 is 1.007 of alpha.23. A single round
ranges about 7 % either side on one binary (alpha.23 read 0.795 in one round of pass 2, as alpha.69
read 0.80 in the third round of the A/B, which alone made its 1.072).
